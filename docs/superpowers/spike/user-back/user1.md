# 拾阅 W0 Spike 体验反馈 — 用户1：小王（研究生/Zotero用户）

## 评分(1-5 分,5 最好)

| 维度 | 分数(1-5) | 说明 |
|---|---|---|
| 1. 打开速度 | 3 | 10页以内的短文档感觉还行，但我平时读的论文基本都是20-40页带大量图表的，打开的时候能明显感觉到"愣"一下，大概有1-2秒的白屏。试了一篇50页的survey，等了快3秒才渲染完。跟Zotero内置阅读器比慢不少，跟浏览器原生PDF预览比更是差一截。 |
| 2. 滚动流畅度 | 2 | 这是我最不满意的地方之一。快速滚动的时候滚动条会抖，视觉上很不舒服，有种页面在"打嗝"的感觉。慢慢滑还行，但一旦用触控板快速swipe就能感受到帧率不够。读长论文的时候需要频繁跳页，这个体验比较影响效率。 |
| 3. 文字选择可用性 | 2 | 能选中文字，但选区的精度问题太多了。英文论文里选一个句子，选区框左右两边跟实际文字位置有偏移，看着就像没对齐。而且英文字体本身就小，选区框在垂直方向上也跟字不齐，有时候选区框比字高出一截，有时候又把字切了一部分。最严重的是选到行尾或者靠近页面边缘的时候，选区会突然"吞掉"下面好几行甚至整页，这个完全不可控。我试了一下想精确选一个段落来做高亮笔记，反复调了好几次才选对，这个在实际工作流里是不能接受的。 |
| 4. 中文选区质量(若测了中文) | 2 | 中文比英文还糟糕一些。中文行尾的选区特别容易"失控"，我选最后几个字的时候经常把下面三四行都带上了。感觉是行尾坐标计算有bug，中文字符宽度跟英文不一样，可能选区的hitbox没做好CJK适配。另外中文PDF本身字体嵌入就比较复杂，有些文档里字体名拿到的是乱码，不知道会不会影响选区计算。 |
| 5. 总体体验 | 2.5 | 能看出来这是一个spike版本，核心功能都有但完成度还不够。作为"能用"的PDF阅读器，勉强及格；但作为一个想替代我现有工作流的工具，差距还比较大。 |

## 开放反馈

### 最让你觉得好用的地方？

说实话，**在Obsidian里直接打开PDF这个想法本身就很有吸引力**。我现在的工作流是Zotero管文献 + Zotero内置阅读器标注 + 再手动把笔记整理到Obsidian里，中间有一个断层。如果拾阅能做好的话，至少在"阅读-标注-笔记"这个链路上能少切一次窗口。

另外我注意到有AI侧边栏的功能，虽然这次没深度测，但方向是对的。如果能做到选中一段文字直接问AI"这段的核心论点是什么"或者"跟XX论文的方法有什么区别"，这个对读论文的效率提升会很大。

### 最让你不爽的地方？

按优先级排：

1. **文字选区质量太差了**。这不是小瑕疵，这是核心功能的可用性问题。读论文最核心的动作就是"选中一段话 → 高亮/做笔记"，如果选区都对不准，后面的功能全白搭。尤其是行尾和页面边缘的误选问题，会让人产生一种"这个工具不靠谱"的直觉。

2. **每次都要 `Cmd+P` 打开，没有文件关联**。我vault里有几十个PDF，每次都要先打命令面板再选文件，这个操作路径太长了。理想的交互是：在文件列表里点击 `.pdf` 文件就直接用拾阅打开，就像Obsidian原生打开markdown一样自然。

3. **每次打开都新开一个view区域**。我的Obsidian工作区通常是左边文件列表、中间笔记、右边有时候放大纲或者反向链接。每次打开PDF都会把布局挤掉，要手动拖来拖去。应该是在当前编辑区以新标签页的形式打开，这才符合Obsidian的交互范式。

4. **界面太简陋了**。没有页码显示、没有缩放控制、没有页面缩略图侧边栏、没有搜索。我理解spike阶段可能故意精简了，但至少页码和缩放得有吧，不然连"翻到第几页"这种基本操作都做不了。

### 你会用它替代现在的 PDF 阅读/笔记方式吗？为什么？

**现阶段不会。** 原因很实际：

- Zotero的PDF阅读器虽然不花哨，但选区精准、滚动流畅、支持搜索和目录跳转，这些基本功都很扎实
- 我的Zotero里有200多篇文献的标注数据，迁移成本很高
- 拾阅目前的完成度还撑不起一个完整的"阅读→标注→笔记"工作流

**但我会持续关注后续版本。** 如果能做到以下几点，我会考虑切换：
- 选区精度达到Zotero同等水平
- 支持目录/大纲导航
- 高亮标注能自动同步为Obsidian笔记（最好是带页码引用的格式）
- 滚动性能优化到不卡顿

### 你愿意为这样一个工具(加上未来的 AI 高亮/笔记)付费吗？心理价位？

**目前的功能不愿意付费。** 坦率说，单纯的"PDF阅读器+高亮选区"在2024年不是一个有付费价值的功能，开源和免费方案太多了。加上AI侧边栏辅助阅读，如果只是调GPT API做翻译和总结，我自己配一个快捷指令也能实现差不多的效果。

**如果未来能做到以下水平，我愿意付费：**
- 基于文献内容的深度问答（不是简单的翻译/总结，而是能理解论文结构、方法论、实验设计）
- 跨文献的知识关联（比如自动发现我vault里哪些论文用了类似方法、引用了同一篇参考文献）
- 高亮标注 → 结构化笔记的自动生成（不是简单摘抄，而是能整理成"方法对比表"、"关键发现时间线"之类的格式）

**心理价位：** 如果做到上面这些，年付 ¥128-198 可以接受。按月订阅的话 ¥15/月左右。超过 ¥200/年的话就得掂量一下了，毕竟Zotero本身是免费的，而且学生党预算有限。

### 额外发现的问题

1. **没有深色模式适配**。我的Obsidian用的是深色主题，但PDF渲染区域还是白底，在暗环境下很刺眼。这不是什么大问题但确实影响长时间阅读的舒适度。

2. **不确定有没有做虚拟滚动/懒加载**。从大文件渲染慢这个现象来看，怀疑是把所有页面都一次性渲染了。如果是的话，建议做viewport-based的按需渲染，只渲染可视区域±1-2页，这个对性能提升会非常明显。

3. **触控板双指缩放没反应**。在MacBook上习惯用双指捏合来放大PDF看细节，但试了一下没效果。

4. **选区之后没有上下文菜单**。选中文字后我期望能弹出一个工具栏（复制/高亮/加笔记/问AI），但现在选完什么都没发生，只是画了个框。

### 其他

我觉得这个PDF阅读器是多余的，其实在现在这样知识更新迅速的时代，人类摄取信息的速度早就跟不上了。就跟coding一样，人都不会真的去review代码了。我就想有一个工具能让我不用逐字阅读这本书，就能知道讲的什么，核心内容、主体思想、要点重点等。
